# Learning guide

Make small edits and preview after each one. Commit a known-good version before trying an exercise so you can inspect or undo changes.

## Checkpoint 1: Find your way around

Open index.html and locate the hero, services, portfolio, FAQ, and contact sections. Change one sentence. Checkpoint: your copy changes without breaking the heading or layout.

## Checkpoint 2: Tune the palette

In css/styles.css, change the gold variable near the top to another muted accent. Review buttons, links, and the hero. Checkpoint: accent color stays restrained and readable.

## Checkpoint 3: Add a real project

Replace the portfolio placeholder only when there is an approved, accurate example. Include project context and what was built, without inventing metrics. Checkpoint: a new visitor can understand the work.

## Checkpoint 4: Make contact real

Change contactEmail in js/config.js to a monitored inbox. Click the email link in the preview. Checkpoint: a mail draft opens to the intended address. This is not a form submission.

## Checkpoint 5: Check access

Use Tab and Enter to move through the page. Expand FAQ items. Resize to a narrow phone width and turn on reduced motion. Checkpoint: all content remains available and the decorative hero stays calm.

## Checkpoint 6: Publish thoughtfully

Follow DEPLOYMENT.md and SEO_GUIDE.md. Replace the domain consistently after the final domain is live. Checkpoint: canonical and sitemap addresses match HTTPS and no sample inbox or domain remains.

## Suggested topics

Learn semantic HTML landmarks and heading order, CSS Grid and media queries, the path from pointer coordinates to CSS variables, and Git status, diff, commit, push, and revert. If you add a hosted form, learn its privacy implications and spam controls.
